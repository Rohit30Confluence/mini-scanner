# Security Policy

Thank you for helping keep Mini Scanner secure.

This document explains how to report security vulnerabilities and what you can expect after reporting them.

---

# Supported Versions

The following versions are currently supported with security updates.

| Version | Supported |
|----------|-----------|
| 1.x.x | ✅ Yes |
| < 1.0.0 | ❌ No |

---

# Reporting a Security Vulnerability

Please **do not** report security vulnerabilities through public GitHub issues.

Instead, report them responsibly by contacting:

**Email**

dinde.infosec@gmail.com

Please include:

- A detailed description of the issue
- Steps to reproduce
- A proof of concept (if applicable)
- Affected version
- Operating system
- Python version
- Any relevant logs or screenshots

---

# Response Process

After receiving a report, we aim to:

- Acknowledge receipt within **72 hours**
- Investigate the issue
- Assess the impact and severity
- Develop and test a fix
- Release a patched version when appropriate
- Credit the reporter (if they wish)

Response times may vary depending on the complexity of the issue.

---

# Responsible Disclosure

Please:

- Give us reasonable time to investigate and fix the issue.
- Avoid publicly disclosing vulnerabilities before a fix is available.
- Do not access, modify, or destroy data that does not belong to you.
- Do not perform denial-of-service (DoS) attacks.
- Do not violate any applicable laws or regulations.

We appreciate responsible disclosure and collaboration.

---

# Scope

Security reports may include issues such as:

- Input validation flaws
- Denial-of-service vulnerabilities
- Resource exhaustion
- Thread-safety issues
- Memory leaks
- Packaging vulnerabilities
- Dependency vulnerabilities
- Logging or information disclosure
- Unsafe defaults
- Authentication or authorization issues (if added in future versions)

---

# Out of Scope

The following are generally considered out of scope:

- Issues caused by unsupported Python versions
- Problems introduced by third-party modifications
- Feature requests
- General coding style suggestions
- Theoretical vulnerabilities without a practical impact

---

# Security Best Practices

When using Mini Scanner:

- Scan only systems that you own or are explicitly authorized to assess.
- Keep your Python environment and dependencies up to date.
- Review scan results before acting on them.
- Follow your organization's security policies and applicable laws.

---

# Security Updates

Security fixes will be released as patch versions whenever possible.

Examples:

- 1.0.1
- 1.0.2
- 1.1.3
